#### <font color="#FFB100">Что такое протокол</font>

- Машина - компьютер на сленге программистов.
- Сервер - специальная машина, существующая для хранения информации и обработки запросов от клиентов.
- Клиент - браузер на машинах пользователей.
- Протоколы  -  договорённость, которая определяет, как машины общаются друг с другом.
- HTTP (HyperText Transfer Protocol) - самый популярный протокол, используемый для передачи веб-страниц и других объектов в интернете.
- Адрес сайта в интернете начинается с http или https, где https - безопасная версия.
- Веб-страницы и другие объекты в интернете имеют особые имена - URL.
- Браузер преобразует запрос пользователя в HTTP-запрос, который отправляется серверу.
- Сервер выполняет действия и возвращает HTTP-ответ, который представляет собой веб-страницу с результатами поиска.
#### <font color="#FFB100">Подробнее об URL</font>
- Адреса URL могут быть короткими и простыми, например [https://ya.ru/white](https://ya.ru/white), или длинными и сложными, как [https://yandex.ru/search/?text=что%20такое%20backend&lr=213](https://yandex.ru/search/?text=%D1%87%D1%82%D0%BE%20%D1%82%D0%B0%D0%BA%D0%BE%D0%B5%20backend&lr=213)
- В начале указывается протокол, обычно это HTTP или HTTPS.
- Имя сервера - yandex.ru.
- Идентификатор запрашиваемого ресурса - /search/.
- После вопросительного знака могут идти параметры, они отделяются друг от друга символом &.
- Кодирование URL: если в URL применяются "запрещённые" символы, их кодируют с помощью "разрешённых".
#### <font color="#FFB100">Кириллица в адресной строке</font>
- Кириллица в адресах может вызывать проблемы при отображении.
- Браузеры и Python-библиотека urllib.parse могут кодировать и декодировать адреса.
- Функция quote() из urllib.parse заменяет запрещенные символы на допустимые.
- Функция unquote() из urllib.parse преобразует закодированные символы в читаемые.
```python
import urllib.parse

strings = [
    'Что такое backend',
    'Привет!',
    ' ',        # Просто пробел.
    'letiště',  # Аэропорт по-чешски.
    'München',  # Крупнейший город Баварии.
    'Champs-Élysées',  # Елисейские поля.
    '東京',     # А это Токио.
]

for s in strings:
    encoded = urllib.parse.quote(s)          # Зашифрованная строка.
    decoded = urllib.parse.unquote(encoded)  # Расшифрованная обратно строка.
    print(decoded, '-', encoded)
```

#### <font color="#FFB100">Исходный код страницы</font>
- Веб-страницы имеют исходный код, доступный через меню "Разработка" в настройках браузера.
- Браузер получает от сервера страницу, размеченную на языке HTML, и отображает её для пользователя.
- HTML-теги используются для форматирования текста и добавления элементов на веб-страницу.
- В исходном коде страницы можно найти "пасхалку", спрятанную в HTML-комментарии.
- Поиск по коду может быть упрощен с помощью поисковой строки браузера (Ctrl + F в Windows, Cmd + F в MacOS)
#### <font color="#FFB100">HTTP-ответы</font>
- Инструменты разработчика используются для отслеживания HTTP-ответов и заголовков.
- HTTP-ответы содержат исходный код веб-страницы и полезную информацию, такую как статус кода и IP-адрес сервера.
- Заголовки ответов включают информацию о запросе, статусе кода и типе содержимого.
- Изучение HTTP-ответов и заголовков может помочь понять, как работают веб-страницы и как они обрабатываются серверами.
Некоторые заголовки ответа можно понять прямо сейчас:

- **Request URL** — Адрес страницы, которую запросил клиент. Обратите внимание, что здесь все кириллические буквы показываются в закодированном виде (но вы уже умеете их расшифровывать!)
- **Status Code** — Код ответа. `200 Ok` означает, что запрос был обработан успешно. Бывают ещё и другие коды. Вы могли сталкиваться с кодом ошибки `404 Not Found`, когда пытались в браузере открыть несуществующую страницу. Или с `500 Internal Server Error`, если на сервере что-то сломалось. Вообще, кодов ответа довольно много. Почитать о них подробнее можно по ссылке [https://developer.mozilla.org/ru/docs/Web/HTTP/Status](https://developer.mozilla.org/ru/docs/Web/HTTP/Status)
- **Remote Address** — IP-адрес сервера в интернете.
- **date** — Дата и время, когда сервер создал ответ на запрос браузера.
- **content-type** — Тип содержимого ответа. Что именно шлёт сервер — чаще всего текст в формате HTML, а также картинки в PNG или JPEG.
#### <font color="#FFB100">HTTP-запросы</font>
- В "Инструментах разработчика" можно разобрать Request Headers запроса, отправленного браузером серверу.
- Заголовок accept-language содержит список языков, на которых браузер готов принять ответ.
- q - параметр, определяющий языковые предпочтения браузера, используется для указания порядка предпочтения языков.
- Request Method говорит о методе запроса, в данном случае использовался метод GET протокола HTTP.
- Метод GET - самый распространённый в интернете, используется, когда клиент хочет отправить запрос, но не собирается записывать что-то на сервер.
- Бэкенд-разработчик отвечает за программы, работающие на серверной стороне.
#### <font color="#FFB100">Методы HTTP-запросов</font>
- HTTP-запросы используются для обмена информацией между сервером и клиентом.
- GET-запросы используются для получения информации от сервера, а POST-запросы для сохранения или изменения данных.
- Запросы и ответы можно увидеть в панели Developer Tools в браузере.
- GET-запрос отправляет браузер, когда пользователь вводит адрес сайта в адресной строке и нажимает Enter.
- POST-запрос используется для сохранения или изменения данных на сервере, например, при отправке сообщения в социальную сеть.
- GET-запрос содержит всю информацию в URL, а POST-запрос передает данные в теле запроса на сервер.
- Сервер обрабатывает или отклоняет запросы в зависимости от типа запроса и корректности данных.

#### <font color="#FFB100">Передаём параметры в URL</font>
- Python позволяет удобно формировать адреса URL с параметрами из словаря.
- Функция get() производит нужные преобразования, нужно лишь передать параметры через именованный аргумент params.
- Бывают такие параметры, которым не нужно присваивать значение, а достаточно передать только имя.
- Для таких параметров в словаре в качестве значения указывается пустая строка.

```python
import requests

search_parameters = {
    'text': 'что такое backend',
    'lr': 213
}
url = 'https://yandex.ru/search/'
# Функция get() приняла на вход URL и параметры поиска,
# а дальше она знает, что делать
response = requests.get(url, params=search_parameters)

print(response.status_code)
print(response.url)
```

#### <font color="#FFB100">Обработка ошибок</font>

- Ошибки в программах могут возникать из-за внешних факторов и не всегда проявляются с первого раза.
- Runtime error - семейство ошибок, которые возникают во время выполнения программы.
- Примеры ошибок: деление на ноль (ZeroDivisionError) и ошибка в области определения функции (ValueError).
- Python создает объект "исключение", когда функция дает сбой, и программа останавливается.
- Исключения используются для информирования разработчика об ошибке и реагирования на нее по инструкции.
- Для перехвата исключений применяется конструкция try - except.
- Инструкции по обработке исключений можно устанавливать для каждого типа отдельно.

```python
try:
    # Здесь написан код, который в некоторых ситуациях
    # может создать исключение (может "выбросить исключение", как говорят разработчики).
    # Программа попробует (try) выполнить этот код.
except TypeError1:
    # Здесь описываем, что следует делать,
    # если будет "выброшено" исключение типа TypeError1.
except TypeError2:
      # А здесь разработчик описывает, как быть, если перехвачено
    # исключение типа TypeError2.
```

def calc_share(apples, friends):

#####  (•) Скорость разработки

Проект на Django состоит из приложений — блоков, как в конструкторе «Лего». Достаточно один раз написать полезное приложение — и можно использовать его в разных проектах, немного доработав.

А иногда и писать ничего не надо: тысячи приложений уже написаны другими разработчиками и выложены в свободный доступ на сайте [Django Packages](https://djangopackages.org/). Достаточно лишь найти и подключить подходящее.

#####  (•) Сообщество

Django появился в 2005 году. С тех пор тысячи специалистов решили сотни тысяч задач и поделились своим опытом в интернете. Если возник вопрос, стоит лишь поискать в сети, и ответ найдётся. Поиск ответов на вопросы — одна из важных составляющих профессии разработчика; при работе с Django поиск почти всегда даст результат.

#####  (•) Настраиваемая админка

Система управления проектом (админ-зона проекта, «админка») в Django создаётся с минимальными усилиями. При необходимости её можно гибко настроить.

##### (•) Работа с базами данных

С базами данных Django общается через инструмент **Django ORM** (англ. _Object-Relational Mapping, «_объектно-реляционное отображение»). Это «переводчик» с языка Python на язык SQL, понятный большинству баз данных. Благодаря Django ORM все запросы к базе данных можно писать прямо на Python.

##### (•) Иногда Django — не лучший выбор

Минусы любого фреймворка — это следствие его плюсов:

- Django — тяжёлый. Это расплата за то, что в «базовую комплектацию» Django включено множество готовых инструментов (например, ORM, админ-панель, система шаблонов). Они могут даже не пригодиться в конкретном проекте, особенно если он небольшой или требует специфических решений.
- Django — медленный. Из-за своей многофункциональности и архитектурных особенностей Django может уступать в производительности более легковесным или асинхронным фреймворкам. Многие современные фреймворки (например, **FastAPI**) работают быстрее, особенно при большом количестве одновременных запросов.

Когда стоит рассмотреть альтернативы?

- **FastAPI**: если вам нужна максимальная производительность, особенно для создания API. FastAPI построен на современных возможностях Python (type hints, async/await), что обеспечивает высокую скорость работы и удобство разработки. FastAPI автоматически генерирует интерактивную документацию для вашего API (Swagger UI, ReDoc).
- **Flask**: если вы начинаете небольшой проект или вам нужна большая гибкость и минимум предустановленных компонентов. Этот микрофреймворк предоставляет только самую необходимую базу, а остальные компоненты (ORM, формы, аутентификация) вы можете выбирать и подключать самостоятельно. Это даёт больше контроля, но требует больше времени на настройку.
#### <font color="#FFB100">Создание Django-проекта</font>

(•) Развёртывание Django-проекта выполняется в несколько простых шагов:
1. Создайте в папке _Dev_ (она уже есть на вашем компьютере) отдельную директорию _jump_into_django._ Это будет **корневая директория проекта,** в ней будет храниться всё, что касается проекта: папка с виртуальным окружением, служебные файлы и рабочая директория — папка с кодом проекта.
2. В корневой директории проекта создайте виртуальное окружение. Откройте консоль, перейдите в корневую директорию проекта _Dev/jump_into_django/_ и выполните команду
    - Linux/macOS: `python3 -m venv venv`;
    - Windows: `python -m venv venv` или `py -3 -m venv venv`.
3. Активируйте виртуальное окружение: из директории _Dev/jump_into_django_ выполните команду:
    - Linux/macOS: `source venv/bin/activate`;
    - Windows: `source venv/Scripts/activate`.
4. Обновите пакетный менеджер: при создании виртуального окружения будет использоваться та версия менеджера, которая была установлена вместе с Python. И это будет, скорее всего, не самая последняя версия, о чём вам и будет сообщаться каждый раз при обращении к нему. Обновить версию можно командой
    - Linux/macOS: `python3 -m pip install --upgrade pip`;
    - Windows: `python -m pip install --upgrade pip`.
5. В активированном виртуальном окружении разверните фреймворк Django версии 3.2.16: `pip install Django==3.2.16`.
6. Создайте Django-проект командой: `django-admin startproject acme_project` (название может быть любым, для тренировки пусть будет _acme_project_).

(•) В результате в **корневой директории проекта** будет создана папка с виртуальным окружением и **рабочая папка проекта** — директория, где хранятся файлы Django-проекта.
- В директории `acme_project` лежат файлы с кодом проекта.
- `acme_project/manage.py` — файл управления Django-проектом из командной строки. Работа с базой данных, запуск встроенного сервера разработки, создание `приложений` — все эти операции будем выполнять через вызов этого файла.
- Пустой файл `acme_project/acme_project/__init__.py` объявляет эту директорию `пакетом Python`.
- В файле `acme_project/acme_project/urls.py` настраиваются `URL проекта`.
- `acme_project/acme_project/wsgi.py` и `acme_project/acme_project/asgi.py` — файлы конфигурации, они пригодятся при размещении проекта на веб-сервере.
- В файле `acme_project/acme_project/settings.py` хранятся все настройки проекта. При развёртывании проекта устанавливаются стандартные настройки; в ходе разработки их изменяют или дополняют. В быту этот файл называют «конфиг» или «сеттинг», хотя более педантичные программисты говорят «файл настроек» или «файл конфигурации проекта». Но таких программистов мало.

#### <font color="#FFB100">Приложения в Django-проекте</font>
- Django-проекты состоят из отдельных приложений (apps) для выполнения отдельных задач.
- Независимые приложения легко дополняются и используются повторно.
- Хорошо спроектированное приложение решает только одну задачу и легко переносится.
- Плохо спроектированное приложение может быть сложным для повторного использования.
- Создание первого приложения включает придумывание имени, генерацию структуры файлов и регистрацию в проекте.
- Хорошо спроектированное приложение должно обрабатывать только одну задачу.
- Создание Django-проекта включает множество файлов и доступ к ним в тренажере.
- Работа над заданием в тренажере включает написание или изменение кода и отправку на проверку.
- Если неудобно работать над заданием в тренажере, можно скачать проект на компьютер и выполнить задание в настольном редакторе.

```python
# Вызываем управляющий файл manage.py;
# startapp catalog — команда «создать приложение с именем catalog».
python manage.py startapp catalog
```

##### (•) Команда `startapp` создаёт базовую структуру файлов, которая, по мнению разработчиков Django, пригодится для любого приложения. При этом никакой магии не происходит: все эти файлы можно создать и вручную, но автоматически — удобнее и быстрее.

- `migrations/` — хранит историю изменений структуры таблиц базы данных, относящихся к приложению;
- `__init__.py` — указывает интерпретатору Python, что этот каталог — пакет Python;
- `admin.py` — настройки админ-зоны приложения;
- `apps.py` — настройки приложения;
- `models.py` — файл для взаимодействия с базой данных;
- `tests.py` — файл для тестов приложения;
- `views.py` — файл для обработчиков запросов.

##### (•) Регистрируем приложение:

Чтобы подключить в проект новое приложение, его нужно зарегистрировать в списке установленных приложений `INSTALLED_APPS` в файле _settings.py_:

```python
# acme_project/settings.py
INSTALLED_APPS = [
    'catalog.apps.CatalogConfig',  # Добавляем эту строчку
    'django.contrib.admin',
    'django.contrib.auth',
    'django.contrib.contenttypes',
    'django.contrib.sessions',
    'django.contrib.messages',
    'django.contrib.staticfiles',
]
```

Строчка `catalog.apps.CatalogConfig` ссылается на класс `CatalogConfig` файла _apps.py_ в папке _catalog_; адрес указывается через точечную нотацию: `директория.файл.класс`:

```python
# catalog/apps.py
from django.apps import AppConfig

class CatalogConfig(AppConfig):
    default_auto_field = 'django.db.models.BigAutoField'
		    name = 'catalog'
```
### <font color="#FFD473">Пути и view-функции</font>
#### <font color="#FFB100">Планирование адресов и конвертеры путей</font>

##### Абсолютный URL

**Абсолютный URL** — полный адрес ресурса:

```
<схема>://<сервер>/<путь>
```

Пример:

```
https://docs.djangoproject.com/en/3.2/topics/http/urls/
```

Состоит из:

- протокол (http/https),
- домен,
- путь к ресурсу.


##### Относительный URL

**Относительный URL** — адрес внутри сайта без домена.

Примеры:

- `install/` → переход на вложенную страницу
- `../` → на уровень выше

**Плюс:** при переносе сайта на другой домен ссылки менять не нужно.

---

##### Маршрутизатор Django

**Маршрутизатор** — список URL, на которые сервер умеет отвечать.  
**View-функция** — функция, которая обрабатывает запрос и возвращает ответ.

Для связи адреса запроса и обработчика применяется функция `path()`. Она принимает обязательные параметры `route` и `view`:

- **route** — шаблон обрабатываемого адреса, это строка-образец, с которой сравнивается полученный запрос. По-русски её называют **маршрут** или **роут**.
- **view** — функция-обработчик: если запрошенный URL совпадает с **route**, вызов будет перенаправлен в указанную view-функцию (view-функции в Django хранят в файле _views.py_).

Связь URL и view:

```python
path('относительный_адрес', <имя обработчика>)
```

Пример:

```python
path('about/', views.about)
```

При переходе на `/about/` вызовется функция `about()`.
Django будет искать главный файл _urls.py_ по адресу, который указан в константе `ROOT_URLCONF` в файле _settings.py_.

---

##### Где хранятся URL

Список адресов хранится в файле:

```
urls.py
```

В списке:

```python
urlpatterns = [
    path('', views.index),        # главная страница
    path('catalog/', views.catalog),
]
```

Django проверяет адреса **сверху вниз**.  
Если совпадения нет → ошибка **404**.

---

##### Переменные в URL

При обработке однотипных адресов уникальную часть адреса можно сохранять в переменную и передавать её во view-функцию в качестве аргумента. Для этого в шаблоне адреса имя переменной заключают в треугольные скобки `<>`.

Чтобы не создавать тысячи адресов:

```
catalog/1/
catalog/2/
catalog/3/
```

Используют переменные:

```python
path('catalog/<pk>/', views.product_detail)
```

Во view придёт аргумент `pk`.

---

##### Конвертеры пути

Конвертер указывает тип данных переменной.

 Основные конвертеры:

|Конвертер|Описание|Пример|
|---|---|---|
|str|Любая строка|`<str:name>`|
|int|Целое число|`<int:pk>`|
|slug|Буквы, цифры, `-` и `_`|`<slug:category>`|

Примеры:

```python
path('catalog/<int:pk>/', views.product_detail)
path('article/<slug:category>/', views.article_category)
```

Если конвертер не указан → используется `str`.

Можно создавать **свои конвертеры**.

---

##### Конфликты адресов

Django использует **первое совпадение** в `urlpatterns`.

 Пример проблемы:

```python
urlpatterns = [
    path('page/<int:pk>/', views.page_detail),
    path('page/1/', views.page_one),
]
```

`page/1/` никогда не вызовет `page_one`, потому что первый путь перехватит запрос.

**Правило:**

> Более конкретные URL должны быть выше.

---

##### Важно про admin

Django автоматически создаёт путь:

```
admin/
```

Лучше не создавать свои адреса, начинающиеся с `admin/`.

---
#### <font color="#FFB100">Распределение адресов по приложениям</font>
- Файлы urls.py из приложений подключаются к корневому файлу urls.py с помощью функции include().
- Адреса проектируют так, чтобы они соответствовали названиям приложений, в которых эти адреса обрабатываются.
- Django даёт возможность разделить список urlpatterns на части в соответствии с приложениями и хранить эти части в директориях приложений.
- В корневом urls.py указывают ссылки на файлы urls.py приложений.
- При запросе к URL catalog/1/ в корневом файле urls.py сработает путь path('catalog/', include('catalog.urls')).
- Отдельное приложение для главной страницы - homepage - создавать не обязательно.

Чтобы сослаться из корневого _urls.py_ на файлы _urls.py_ приложений, применяют функцию `include()` (англ. «включить», «встроить»); её указывают вторым аргументом в `path()`, вместо имени view-функции:
```python
# Корневой файл urls.py 

# Импортируем встроенные функции include() и path().
from django.urls import include, path

urlpatterns = [    
    # Если на сервер пришёл запрос к главной странице,
    # Django проверит на совпадение с запрошенным URL 
    # все path() в файле urls.py приложения homepage.
    path('', include('homepage.urls')),

    # Если в приложении homepage не найдётся совпадений,
    # Django продолжит искать совпадения здесь, в корневом файле urls.py.

    # Если запрос начинается с catalog/, 
    # Django будет искать совпадения в файле urls.py
    # приложения catalog.
    path('catalog/', include('catalog.urls')),
]
```

Приложение **homepage** создано для одной-единственной задачи: обрабатывать запросы только к главной странице — и ни к каким другим. Поэтому файл _urls.py_ этого приложения будет работать только с одним адресом:

```python
# homepage/urls.py

# Импортируем функцию path() 
# и файл homepage/views.py, в котором объявлена view-функция index().
from django.urls import path

from . import views

urlpatterns = [
    # Если вызван URL без относительного адреса (шаблон — пустые кавычки),
    # то вызывается view-функция index() из файла views.py
    path('', views.index),
]
```

Файл _urls.py_ приложения **catalog**:

```python
# catalog/urls.py
from django.urls import path

from . import views

urlpatterns = [
    # Если пришёл запрос к относительному URL catalog/,
    # то запрос из корневого urls.py перенаправляется сюда, 
    # в файл catalog/urls.py;
    # и если в запросе после 'catalog/' ничего нет (пустая строка),
    # будет вызвана view-функция product_list() из файла catalog/views.py
    path('', views.product_list),

    # Если в запросе после 'catalog/' стоит '1/' или '2/',
    # будет вызвана view-функция product_detail() из файла catalog/views.py
    path('1/', views.product_detail),
    path('2/', views.product_detail),
]
```
#### <font color="#FFB100">View-фуункции: от запроса до ответа</font>
- Django обрабатывает запросы в порядке: чтение списка urlpatterns, поиск шаблона пути, вызов view-функции, возврат ответа.
- View-функция - это функция, обрабатывающая запросы и возвращающая ответ пользователю.
- View-функции хранятся в файле views.py, который может быть разделен на приложения.
- Объект запроса - HttpRequest, содержит информацию о запросе, включая URL, метод запроса и другие атрибуты.
- Объект ответа - HttpResponse, содержит статус-код, код HTML-страницы и другие данные для браузера.
- Django отслеживает маршруты для обработки запросов, используя файлы urls.py и шаблоны адресов.
- View-функции должны принимать объект запроса и возвращать объект ответа.
- Переменные из шаблонов адресов должны быть переданы в соответствующие view-функции.
### <font color="#FFD473">Вёрстка для бэкендера</font>
#### <font color="#FFB100">Веб-страницы: язык HTML</font>

##### Как формируется ответ пользователю

Путь запроса в Django выглядит так:

1. Пользователь открывает URL.
    
2. Django ищет совпадение в `urls.py`.
    
3. Вызывает соответствующую `view`-функцию.
    
4. `view` возвращает `HttpResponse`.
    
5. Браузер показывает полученный ответ.
    

Пример:

```python
# urls.py
urlpatterns = [
    path('nice/', views.nice_page),
]
```

```python
# views.py
def nice_page(request):
    return HttpResponse('Это nice page, прекраснейшая страница в глобальной сети!')
```

Но просто текстовой строки недостаточно для полноценной веб-страницы — нужен HTML.

---

##### Что такое HTML

**HTML** — это **HyperText Markup Language**, язык гипертекстовой разметки.

Он нужен, чтобы браузер понимал:

- где заголовок,
    
- где абзац,
    
- где ссылка,
    
- где изображение,
    
- как структурировать текст на странице.
    

Сервер отправляет браузеру текст с HTML-разметкой, а браузер превращает его в визуальную страницу.

---

##### Зачем бэкендеру знать HTML

Хотя вёрстка — зона ответственности фронтендера, бэкенд-разработчику HTML тоже нужен:

- для понимания структуры страниц,
    
- для отладки,
    
- для работы с шаблонами,
    
- для правки или разбиения готового HTML-кода,
    
- для создания прототипов интерфейса.
    

---

##### HTML-теги

HTML состоит из **тегов** — специальных меток в угловых скобках.

##### Парные теги

Состоят из открывающего и закрывающего тегов:

```html
<p>Текст абзаца</p>
```

##### Одиночные теги

Не имеют закрывающей части:

```html
<br>
<img src="...">
```

---

##### Базовые теги HTML

##### Заголовки: `h1`–`h6`

Используются для заголовков разных уровней:

```html
<h1>Заголовок страницы</h1>
<h2>Заголовок раздела</h2>
<h3>Заголовок подраздела</h3>
```

- `h1` — самый крупный,
    
- `h6` — самый мелкий,
    
- на практике чаще всего используют `h1`, `h2`, `h3`.
    

---

##### Абзац: `p`

Тег `p` используется для оформления абзацев:

```html
<p>Это абзац текста.</p>
```

Абзацы визуально отделяются друг от друга.

---

##### Комментарии: `<!-- -->`

Комментарии видны в исходном коде, но не показываются пользователю:

```html
<!-- Здесь комментарий для разработчика -->
```

Можно писать и многострочные комментарии.

---

##### Ссылка: `a`

Тег `a` создаёт ссылку:

```html
<a href="https://ya.ru">Перейти на сайт</a>
```

Между тегами находится текст ссылки.

##### Важные атрибуты ссылки

##### `href`

Указывает адрес перехода.

Без `href` ссылка не работает.

##### `target`

Определяет, где откроется ссылка:

- `_self` — в текущей вкладке,
    
- `_blank` — в новой вкладке.
    

Пример:

```html
<a href="https://ya.ru" target="_blank">Открыть в новой вкладке</a>
```

Пустой `href` допустим при отладке:

```html
<a href="">Пустая ссылка</a>
```

---

##### Изображение: `img`

Тег `img` вставляет картинку на страницу:

```html
<img src="image.png">
```

- это одиночный тег;
    
- адрес изображения указывается в атрибуте `src`.
    

Изображение может храниться:

- внутри проекта,
    
- на внешнем сервере.
    

Если картинка хранится на чужом сервере и её удалят, на странице она тоже исчезнет.

---

##### Перенос строки: `br`

Тег `br` принудительно переносит текст на новую строку:

```html
Первая строка<br>Вторая строка
```

---

##### Выделение текста: `b` и `i`

- `b` — полужирный текст,
    
- `i` — курсив.
    

Пример:

```html
<p>Это <b>важный</b> и <i>выделенный</i> текст.</p>
```

---

##### Атрибуты тегов

Атрибуты задают дополнительные свойства тегов.

Правила:

- пишутся в открывающем теге;
    
- могут быть в количестве нескольких;
    
- разделяются пробелами;
    
- порядок не важен;
    
- записываются как `имя="значение"`.
    

Пример:

```html
<a href="https://example.com" target="_blank">Ссылка</a>
```

По кодстайлу Яндекс Практикума значения атрибутов пишут в **двойных кавычках**.

---

##### Вложенность тегов

HTML-теги можно вкладывать друг в друга:

```html
<h2>
  Заголовок, внутри которого <a href="https://ya.ru">ссылка</a>
</h2>
```

Важно соблюдать правильную структуру:

- тег должен закрываться **внутри того блока, где он был открыт**.
    

Для читаемости вложенные теги обычно отбивают отступами.

---

##### Списки

##### Маркированный список: `ul`

```html
<ul>
  <li>Первый пункт</li>
  <li>Второй пункт</li>
</ul>
```

- `ul` — контейнер списка,
    
- `li` — отдельный элемент списка.
    

---

##### Нумерованный список: `ol`

```html
<ol>
  <li>Первый пункт</li>
  <li>Второй пункт</li>
</ol>
```

Отличие от `ul` только в том, что элементы автоматически нумеруются.

---

##### Блочный контейнер: `div`

Тег `div` нужен, чтобы объединять части страницы в логические блоки:

```html
<div>
  <h2>Заголовок блока</h2>
  <p>Текст внутри блока</p>
</div>
```

Его используют для группировки элементов и последующего управления их внешним видом и расположением.

---

##### Как браузер обрабатывает HTML

Браузер:

- интерпретирует HTML-теги,
    
- игнорирует лишние пробелы и переносы строк в коде,
    
- отображает элементы в соответствии с их назначением.
    

Из-за этого текст, просто разбитый по строкам в исходнике, без тегов может отображаться одной строкой.

---

##### Частые ошибки в HTML

##### Неправильное закрытие вложенных тегов

Ошибка:

```html
<p>
  Текст
  <a href="">
    Ссылка
</p>
</a>
```

Проблема: тег `a` открыт внутри `p`, но закрыт снаружи.  
Из-за этого браузер может неправильно разметить страницу.

Правильно:

```html
<p>
  Текст
  <a href="">Ссылка</a>
</p>
```

---

##### Незакрытый парный тег

Ошибка:

```html
<h1>Заголовок
<p>Абзац</p>
```

Если не закрыть `h1`, браузер может решить, что весь последующий текст — это заголовок.

Правильно:

```html
<h1>Заголовок</h1>
<p>Абзац</p>
```

---

##### Главное, что нужно запомнить

- HTML — язык разметки веб-страниц.
    
- Он нужен, чтобы браузер правильно отображал содержимое.
    
- Основа HTML — теги.
    
- Теги бывают парные и одиночные.
    
- Важные теги:
    
    - `h1`–`h6`,
        
    - `p`,
        
    - `a`,
        
    - `img`,
        
    - `br`,
        
    - `b`,
        
    - `i`,
        
    - `ul`, `ol`, `li`,
        
    - `div`.
        
- Атрибуты задают дополнительные свойства тегов.
    
- Теги можно вкладывать, но их нужно правильно закрывать.
    
- Частые ошибки:
    
    - нарушенная вложенность,
        
    - забытый закрывающий тег.

```html
<h1>Заголовок</h1>
<p>Абзац текста</p>
<a href="https://example.com">Ссылка</a>
<img src="image.jpg">
<br>
<b>Жирный текст</b>
<i>Курсив</i>

<ul>
  <li>Пункт списка</li>
</ul>

<ol>
  <li>Пункт списка</li>
</ol>

<div>
  Блок контента
</div>
```

Могу сразу сделать и **третью суммаризацию в таком же стиле**, если пришлёшь следующий урок.
#### <font color="#FFB100">Структура HTML-документа</font>

##### Базовая структура HTML-страницы

HTML-документ строится по стандартной схеме:

```html
<!DOCTYPE html>
<html lang="ru">
  <head>
    <!-- служебная информация -->
  </head>
  <body>
    <!-- содержимое страницы -->
  </body>
</html>
```

 `<!DOCTYPE html>`

Сообщает браузеру, что документ написан на **HTML5**.

`<html lang="ru">`

Корневой тег всей страницы.  
Атрибут `lang` указывает язык содержимого страницы.

`<head>`

Содержит **служебную информацию** о странице.

 `<body>`

Содержит всё, что **видит пользователь** в браузере.

---

##### Тег `<head>`: служебная часть страницы

Содержимое `head` обычно не видно пользователю напрямую.  
Исключения:

- заголовок вкладки (`title`),
    
- favicon.
    

В `head` размещают:

- метаданные,
    
- кодировку,
    
- описание страницы,
    
- заголовок вкладки,
    
- ссылки на служебные файлы.
    

---

##### Метатеги `<meta>`

Метатеги описывают служебные свойства страницы.

 Кодировка страницы:

```html
<meta charset="utf-8">
```

Указывает браузеру кодировку документа.  
Это нужно, чтобы текст на кириллице и других нелатинских языках отображался корректно.

 Зачем это нужно

Если не указать кодировку, браузер может определить её неправильно, и появятся **кракозябры** вместо нормального текста.

---

##### Описание страницы

```html
<meta name="description" content="Краткое описание страницы">
```

Используется для краткого анонса содержимого страницы.  
Часто это описание показывается в результатах поисковой выдачи.

---

##### Тег `<title>`

```html
<title>Заголовок страницы</title>
```

Текст из `title` отображается:

- на вкладке браузера,
    
- в названии окна/вкладки,
    
- часто используется поисковыми системами.
    

---

##### Favicon и тег `<link>`

Favicon — маленькая иконка сайта на вкладке браузера.

Пример подключения:

```html
<link rel="icon" href="fav.ico" type="image">
```

Современные браузеры часто используют иконки разных размеров:

```html
<link rel="icon" href="fav.ico" type="image">
<link rel="apple-touch-icon" sizes="180x180" href="/apple-touch-icon.png">
<link rel="icon" type="image/png" sizes="32x32" href="/favicon-32x32.png">
<link rel="icon" type="image/png" sizes="16x16" href="/favicon-16x16.png">
```

##### Что важно запомнить

- favicon подключается через `<link>`;
    
- могут использоваться форматы `.ico`, `.png`, `.gif`;
    
- обычно набор иконок готовят дизайнеры и верстальщики.
    

---

##### Тег `<body>`: видимая часть страницы

В `body` находится весь контент, который отображается пользователю:

- текст,
    
- картинки,
    
- меню,
    
- блоки сайта,
    
- статьи,
    
- ссылки и т.д.
    

---

##### Семантическая структура страницы

Для логического деления страницы используют специальные теги.

 `<header>`

Верхняя часть страницы, «шапка сайта».  
Часто содержит:

- логотип,
    
- контакты,
    
- навигацию.
    

---

 `<nav>`

Блок навигации.  
Сюда обычно помещают меню сайта.

---

 `<main>`

Основное содержимое страницы.  
Это главная смысловая часть документа.

Внутри `main` могут быть:

 `<section>`

Раздел страницы.

 `<article>`

Отдельный самостоятельный материал, например статья или пост.

 `<div>`

Универсальный контейнер для группировки элементов.

---

 `<aside>`

Блок с дополнительной, косвенно связанной информацией:

- боковая колонка,
    
- подсказки,
    
- дополнительные ссылки,
    
- реклама,
    
- виджеты.
    

---

 `<footer>`

Нижняя часть страницы, «подвал».  
Обычно содержит:

- копирайт,
    
- год,
    
- контакты,
    
- служебные ссылки,
    
- иногда повторную навигацию.
    

---

#####  Пример полной структуры страницы

```html
<!DOCTYPE html>
<html lang="ru">
  <head>
    <meta charset="utf-8">
    <meta name="description" content="Краткое описание страницы">
    <title>Заголовок для отображения в названии вкладки</title>
    <link rel="icon" href="fav.ico" type="image">
    <link rel="apple-touch-icon" sizes="180x180" href="/apple-touch-icon.png">
    <link rel="icon" type="image/png" sizes="32x32" href="/favicon-32x32.png">
    <link rel="icon" type="image/png" sizes="16x16" href="/favicon-16x16.png">
  </head>
  <body>
    <header>
      Верхняя часть страницы
      <nav>
        Меню сайта
      </nav>
    </header>
    <main>
      Основное содержимое страницы
    </main>
    <footer>
      Подвал сайта
    </footer>
  </body>
</html>
```

---

##### Зачем нужны семантические теги

Теги `header`, `main`, `footer`, `nav`, `aside`, `section`, `article` сами по себе **не меняют внешний вид** содержимого.  
Они нужны для **структуры и смысла**.

##### Польза семантической разметки

 Для пользователей

Людям с ограниченными возможностями проще ориентироваться на странице, особенно при использовании экранных дикторов.

 Для разработчиков

Код становится понятнее и удобнее для поддержки.

 Для поисковых систем

Поисковым роботам проще понимать, где основное содержимое, а где служебные части страницы.

---

##### `div` или семантические теги

С технической точки зрения можно почти всё сверстать через `div`.  
Ошибка не возникнет.

Но правильнее использовать **семантические теги по назначению**, потому что это:

- улучшает читаемость кода,
    
- помогает доступности,
    
- полезно для SEO,
    
- делает структуру страницы более понятной.
    

---

##### Главное, что нужно запомнить

- HTML-документ начинается с `<!DOCTYPE html>`.
    
- Весь код страницы находится внутри `<html>`.
    
- Страница делится на две основные части:
    
    - `<head>` — служебная информация,
        
    - `<body>` — видимое содержимое.
        
- В `head` часто используют:
    
    - `<meta charset="utf-8">`,
        
    - `<meta name="description" ...>`,
        
    - `<title>`,
        
    - `<link>` для favicon.
        
- В `body` применяют семантические теги:
    
    - `header`,
        
    - `nav`,
        
    - `main`,
        
    - `section`,
        
    - `article`,
        
    - `aside`,
        
    - `footer`.
        
- Семантическая вёрстка удобнее и полезнее, чем сплошные `div`.
    

---

##### Короткая шпаргалка

```html
<!DOCTYPE html>
<html lang="ru">
  <head>
    <meta charset="utf-8">
    <meta name="description" content="Описание страницы">
    <title>Заголовок вкладки</title>
    <link rel="icon" href="favicon.ico" type="image">
  </head>
  <body>
    <header>Шапка</header>
    <nav>Навигация</nav>
    <main>
      <section>Раздел</section>
      <article>Статья</article>
      <aside>Дополнительно</aside>
    </main>
    <footer>Подвал</footer>
  </body>
</html>
```
