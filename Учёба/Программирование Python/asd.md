#### <font color="#FFB100">Что такое протокол</font>

- Машина - компьютер на сленге программистов.
- Сервер - специальная машина, существующая для хранения информации и обработки запросов от клиентов.
- Клиент - браузер на машинах пользователей.
- Протоколы  -  договорённость, которая определяет, как машины общаются друг с другом.
- HTTP (HyperText Transfer Protocol) - самый популярный протокол, используемый для передачи веб-страниц и других объектов в интернете.
- Адрес сайта в интернете начинается с http или https, где https - безопасная версия.
- Веб-страницы и другие объекты в интернете имеют особые имена - URL.
- Браузер преобразует запрос пользователя в HTTP-запрос, который отправляется серверу.
- Сервер выполняет действия и возвращает HTTP-ответ, который представляет собой веб-страницу с результатами поиска.
#### <font color="#FFB100">Подробнее об URL</font>
- Адреса URL могут быть короткими и простыми, например [https://ya.ru/white](https://ya.ru/white), или длинными и сложными, как [https://yandex.ru/search/?text=что%20такое%20backend&lr=213](https://yandex.ru/search/?text=%D1%87%D1%82%D0%BE%20%D1%82%D0%B0%D0%BA%D0%BE%D0%B5%20backend&lr=213)
- В начале указывается протокол, обычно это HTTP или HTTPS.
- Имя сервера - yandex.ru.
- Идентификатор запрашиваемого ресурса - /search/.
- После вопросительного знака могут идти параметры, они отделяются друг от друга символом &.
- Кодирование URL: если в URL применяются "запрещённые" символы, их кодируют с помощью "разрешённых".
#### <font color="#FFB100">Кириллица в адресной строке</font>
- Кириллица в адресах может вызывать проблемы при отображении.
- Браузеры и Python-библиотека urllib.parse могут кодировать и декодировать адреса.
- Функция quote() из urllib.parse заменяет запрещенные символы на допустимые.
- Функция unquote() из urllib.parse преобразует закодированные символы в читаемые.
```python
import urllib.parse

strings = [
    'Что такое backend',
    'Привет!',
    ' ',        # Просто пробел.
    'letiště',  # Аэропорт по-чешски.
    'München',  # Крупнейший город Баварии.
    'Champs-Élysées',  # Елисейские поля.
    '東京',     # А это Токио.
]

for s in strings:
    encoded = urllib.parse.quote(s)          # Зашифрованная строка.
    decoded = urllib.parse.unquote(encoded)  # Расшифрованная обратно строка.
    print(decoded, '-', encoded)
```

#### <font color="#FFB100">Исходный код страницы</font>
- Веб-страницы имеют исходный код, доступный через меню "Разработка" в настройках браузера.
- Браузер получает от сервера страницу, размеченную на языке HTML, и отображает её для пользователя.
- HTML-теги используются для форматирования текста и добавления элементов на веб-страницу.
- В исходном коде страницы можно найти "пасхалку", спрятанную в HTML-комментарии.
- Поиск по коду может быть упрощен с помощью поисковой строки браузера (Ctrl + F в Windows, Cmd + F в MacOS)
#### <font color="#FFB100">HTTP-ответы</font>
- Инструменты разработчика используются для отслеживания HTTP-ответов и заголовков.
- HTTP-ответы содержат исходный код веб-страницы и полезную информацию, такую как статус кода и IP-адрес сервера.
- Заголовки ответов включают информацию о запросе, статусе кода и типе содержимого.
- Изучение HTTP-ответов и заголовков может помочь понять, как работают веб-страницы и как они обрабатываются серверами.
Некоторые заголовки ответа можно понять прямо сейчас:

- **Request URL** — Адрес страницы, которую запросил клиент. Обратите внимание, что здесь все кириллические буквы показываются в закодированном виде (но вы уже умеете их расшифровывать!)
- **Status Code** — Код ответа. `200 Ok` означает, что запрос был обработан успешно. Бывают ещё и другие коды. Вы могли сталкиваться с кодом ошибки `404 Not Found`, когда пытались в браузере открыть несуществующую страницу. Или с `500 Internal Server Error`, если на сервере что-то сломалось. Вообще, кодов ответа довольно много. Почитать о них подробнее можно по ссылке [https://developer.mozilla.org/ru/docs/Web/HTTP/Status](https://developer.mozilla.org/ru/docs/Web/HTTP/Status)
- **Remote Address** — IP-адрес сервера в интернете.
- **date** — Дата и время, когда сервер создал ответ на запрос браузера.
- **content-type** — Тип содержимого ответа. Что именно шлёт сервер — чаще всего текст в формате HTML, а также картинки в PNG или JPEG.
#### <font color="#FFB100">HTTP-запросы</font>
- В "Инструментах разработчика" можно разобрать Request Headers запроса, отправленного браузером серверу.
- Заголовок accept-language содержит список языков, на которых браузер готов принять ответ.
- q - параметр, определяющий языковые предпочтения браузера, используется для указания порядка предпочтения языков.
- Request Method говорит о методе запроса, в данном случае использовался метод GET протокола HTTP.
- Метод GET - самый распространённый в интернете, используется, когда клиент хочет отправить запрос, но не собирается записывать что-то на сервер.
- Бэкенд-разработчик отвечает за программы, работающие на серверной стороне.
#### <font color="#FFB100">Методы HTTP-запросов</font>
- HTTP-запросы используются для обмена информацией между сервером и клиентом.
- GET-запросы используются для получения информации от сервера, а POST-запросы для сохранения или изменения данных.
- Запросы и ответы можно увидеть в панели Developer Tools в браузере.
- GET-запрос отправляет браузер, когда пользователь вводит адрес сайта в адресной строке и нажимает Enter.
- POST-запрос используется для сохранения или изменения данных на сервере, например, при отправке сообщения в социальную сеть.
- GET-запрос содержит всю информацию в URL, а POST-запрос передает данные в теле запроса на сервер.
- Сервер обрабатывает или отклоняет запросы в зависимости от типа запроса и корректности данных.

#### <font color="#FFB100">Передаём параметры в URL</font>
- Python позволяет удобно формировать адреса URL с параметрами из словаря.
- Функция get() производит нужные преобразования, нужно лишь передать параметры через именованный аргумент params.
- Бывают такие параметры, которым не нужно присваивать значение, а достаточно передать только имя.
- Для таких параметров в словаре в качестве значения указывается пустая строка.

```python
import requests

search_parameters = {
    'text': 'что такое backend',
    'lr': 213
}
url = 'https://yandex.ru/search/'
# Функция get() приняла на вход URL и параметры поиска,
# а дальше она знает, что делать
response = requests.get(url, params=search_parameters)

print(response.status_code)
print(response.url)
```

#### <font color="#FFB100">Обработка ошибок</font>

- Ошибки в программах могут возникать из-за внешних факторов и не всегда проявляются с первого раза.
- Runtime error - семейство ошибок, которые возникают во время выполнения программы.
- Примеры ошибок: деление на ноль (ZeroDivisionError) и ошибка в области определения функции (ValueError).
- Python создает объект "исключение", когда функция дает сбой, и программа останавливается.
- Исключения используются для информирования разработчика об ошибке и реагирования на нее по инструкции.
- Для перехвата исключений применяется конструкция try - except.
- Инструкции по обработке исключений можно устанавливать для каждого типа отдельно.

```python
try:
    # Здесь написан код, который в некоторых ситуациях
    # может создать исключение (может "выбросить исключение", как говорят разработчики).
    # Программа попробует (try) выполнить этот код.
except TypeError1:
    # Здесь описываем, что следует делать,
    # если будет "выброшено" исключение типа TypeError1.
except TypeError2:
      # А здесь разработчик описывает, как быть, если перехвачено
    # исключение типа TypeError2.
```

def calc_share(apples, friends):

    return apples/friends_number

- Django остается хорошим выбором для создания MVP, но требует времени и усилий для настройки.
### Скорость разработки

Проект на Django состоит из приложений — блоков, как в конструкторе «Лего». Достаточно один раз написать полезное приложение — и можно использовать его в разных проектах, немного доработав.

А иногда и писать ничего не надо: тысячи приложений уже написаны другими разработчиками и выложены в свободный доступ на сайте [Django Packages](https://djangopackages.org/). Достаточно лишь найти и подключить подходящее.

### Сообщество

Django появился в 2005 году. С тех пор тысячи специалистов решили сотни тысяч задач и поделились своим опытом в интернете. Если возник вопрос, стоит лишь поискать в сети, и ответ найдётся. Поиск ответов на вопросы — одна из важных составляющих профессии разработчика; при работе с Django поиск почти всегда даст результат.

### Настраиваемая админка

Система управления проектом (админ-зона проекта, «админка») в Django создаётся с минимальными усилиями. При необходимости её можно гибко настроить.

### Работа с базами данных

С базами данных Django общается через инструмент **Django ORM** (англ. _Object-Relational Mapping, «_объектно-реляционное отображение»). Это «переводчик» с языка Python на язык SQL, понятный большинству баз данных. Благодаря Django ORM все запросы к базе данных можно писать прямо на Python.

## Иногда Django — не лучший выбор

Минусы любого фреймворка — это следствие его плюсов:

- Django — тяжёлый. Это расплата за то, что в «базовую комплектацию» Django включено множество готовых инструментов (например, ORM, админ-панель, система шаблонов). Они могут даже не пригодиться в конкретном проекте, особенно если он небольшой или требует специфических решений.
- Django — медленный. Из-за своей многофункциональности и архитектурных особенностей Django может уступать в производительности более легковесным или асинхронным фреймворкам. Многие современные фреймворки (например, **FastAPI**) работают быстрее, особенно при большом количестве одновременных запросов.

Когда стоит рассмотреть альтернативы?

- **FastAPI**: если вам нужна максимальная производительность, особенно для создания API. FastAPI построен на современных возможностях Python (type hints, async/await), что обеспечивает высокую скорость работы и удобство разработки. FastAPI автоматически генерирует интерактивную документацию для вашего API (Swagger UI, ReDoc).
- **Flask**: если вы начинаете небольшой проект или вам нужна большая гибкость и минимум предустановленных компонентов. Этот микрофреймворк предоставляет только самую необходимую базу, а остальные компоненты (ORM, формы, аутентификация) вы можете выбирать и подключать самостоятельно. Это даёт больше контроля, но требует больше времени на настройку.
#### <font color="#FFB100">Создание Django-проекта</font>

(•) Развёртывание Django-проекта выполняется в несколько простых шагов:
1. Создайте в папке _Dev_ (она уже есть на вашем компьютере) отдельную директорию _jump_into_django._ Это будет **корневая директория проекта,** в ней будет храниться всё, что касается проекта: папка с виртуальным окружением, служебные файлы и рабочая директория — папка с кодом проекта.
2. В корневой директории проекта создайте виртуальное окружение. Откройте консоль, перейдите в корневую директорию проекта _Dev/jump_into_django/_ и выполните команду
    - Linux/macOS: `python3 -m venv venv`;
    - Windows: `python -m venv venv` или `py -3 -m venv venv`.
3. Активируйте виртуальное окружение: из директории _Dev/jump_into_django_ выполните команду:
    - Linux/macOS: `source venv/bin/activate`;
    - Windows: `source venv/Scripts/activate`.
4. Обновите пакетный менеджер: при создании виртуального окружения будет использоваться та версия менеджера, которая была установлена вместе с Python. И это будет, скорее всего, не самая последняя версия, о чём вам и будет сообщаться каждый раз при обращении к нему. Обновить версию можно командой
    - Linux/macOS: `python3 -m pip install --upgrade pip`;
    - Windows: `python -m pip install --upgrade pip`.
5. В активированном виртуальном окружении разверните фреймворк Django версии 3.2.16: `pip install Django==3.2.16`.
6. Создайте Django-проект командой: `django-admin startproject acme_project` (название может быть любым, для тренировки пусть будет _acme_project_).

(•) В результате в **корневой директории проекта** будет создана папка с виртуальным окружением и **рабочая папка проекта** — директория, где хранятся файлы Django-проекта.
- В директории `acme_project` лежат файлы с кодом проекта.
- `acme_project/manage.py` — файл управления Django-проектом из командной строки. Работа с базой данных, запуск встроенного сервера разработки, создание `приложений` — все эти операции будем выполнять через вызов этого файла.
- Пустой файл `acme_project/acme_project/__init__.py` объявляет эту директорию `пакетом Python`.
- В файле `acme_project/acme_project/urls.py` настраиваются `URL проекта`.
- `acme_project/acme_project/wsgi.py` и `acme_project/acme_project/asgi.py` — файлы конфигурации, они пригодятся при размещении проекта на веб-сервере.
- В файле `acme_project/acme_project/settings.py` хранятся все настройки проекта. При развёртывании проекта устанавливаются стандартные настройки; в ходе разработки их изменяют или дополняют. В быту этот файл называют «конфиг» или «сеттинг», хотя более педантичные программисты говорят «файл настроек» или «файл конфигурации проекта». Но таких программистов мало.

Запуск Django-проекта:

```bash
python manage.py runserver # В Windows
# или
python3 manage.py runserver # В Linux/macOS.

# В последующих примерах команд мы будем указывать только один вариант;
# если у вас Windows - пишите python;
# если у вас Linux или macOS - пишите python3.
```

```bash
...
Starting development server at <http://127.0.0.1:8000/>
Quit the server with CTRL-BREAK.
```
#### <font color="#FFB100">Приложения в Django-проекте</font>
- Django-проекты состоят из отдельных приложений (apps) для выполнения отдельных задач.
- Независимые приложения легко дополняются и используются повторно.
- Хорошо спроектированное приложение решает только одну задачу и легко переносится.
- Плохо спроектированное приложение может быть сложным для повторного использования.
- Создание первого приложения включает придумывание имени, генерацию структуры файлов и регистрацию в проекте.
- Хорошо спроектированное приложение должно обрабатывать только одну задачу.
- Создание Django-проекта включает множество файлов и доступ к ним в тренажере.
- Работа над заданием в тренажере включает написание или изменение кода и отправку на проверку.
- Если неудобно работать над заданием в тренажере, можно скачать проект на компьютер и выполнить задание в настольном редакторе.

```python
# Вызываем управляющий файл manage.py;
# startapp catalog — команда «создать приложение с именем catalog».
python manage.py startapp catalog
```

(•) Команда `startapp` создаёт базовую структуру файлов, которая, по мнению разработчиков Django, пригодится для любого приложения. При этом никакой магии не происходит: все эти файлы можно создать и вручную, но автоматически — удобнее и быстрее.

- `migrations/` — хранит историю изменений структуры таблиц базы данных, относящихся к приложению;
- `__init__.py` — указывает интерпретатору Python, что этот каталог — пакет Python;
- `admin.py` — настройки админ-зоны приложения;
- `apps.py` — настройки приложения;
- `models.py` — файл для взаимодействия с базой данных;
- `tests.py` — файл для тестов приложения;
- `views.py` — файл для обработчиков запросов.
